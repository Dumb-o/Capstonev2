### P1.1 — Redis-backed rate limiting middleware

File: `backend/app/middleware/rate_limit.py` (new)

Sliding-window rate limiter using Redis as the counter store.
Configurable per-route limits via `app.state.RATE_LIMITS` (or built-in defaults):

  | Route prefix   | Limit     |
  |----------------|-----------|
  | /api/auth      | 10 req/min |
  | /api/ipfs      | 20 req/min |
  | /api/admin     | 30 req/min |
  | /api/health    | 60 req/min |
  | __default__    | 60 req/min |

Returns `429 Too Many Requests` with a `Retry-After` header when exceeded.
Bypasses OPTIONS preflight requests.

Wired into `main.py` as `app.add_middleware(RateLimitMiddleware)` after CORS.

---

### P1.2 — Periodic IPFS repinning background service

File: `backend/app/services/repin_service.py` (new)

Background `asyncio` loop that runs every 6 hours (configurable via
`settings.repin_interval_seconds`) and:

1. Queries all CIDs from the database:
   - Contract terms (`contracts.terms_cid`)
   - Milestone deliverables (`contract_milestones.deliverable_cid`)
   - User avatars (`users.avatar_cid`)
   - User portfolios (`users.portfolio_cids` — JSON array)
2. Calls `ipfs_service.pin_file(cid)` on each to refresh the pin on the IPFS node.
3. Logs successes and failures.

Started in `main.py` lifespan via `start_repin_service()` (always, unlike
event listener which requires a private key).

Setting added to `config.py`: `repin_interval_seconds: int = 21600`

---

### P1.3 — Mandatory on-chain contract creation

File: `backend/app/services/contract_service.py` (modified)

`create_contract()` previously used a silent `if pk:` guard that skipped
on-chain registration when no private key was configured. Now raises
`ValidationError` with a clear message if no private key is available,
matching the pattern already used by `fund_contract()`.

This ensures every contract is always anchored on-chain and no
off-chain-only records are silently created.
